# Example: a round with two lanes

A complete round, offline, in about 10 seconds: a tiny repository, two task notes, two lanes
with **fake** agents, the review check on each lane, and the cleanup. Nothing of yours is read or
changed. Everything happens in a throw-away folder with its own HOME and its own tmux server.

It is the [first-use manual](../../docs/FIRST-USE.md)'s round, with two workers instead of one.

## Run it

From a checkout of this repository (Linux, WSL or macOS; bash, git, tmux and Python 3.11+):

```sh
bash examples/two-lane-round/run.sh
```

Optionally give it a new folder: `bash examples/two-lane-round/run.sh /tmp/two-lanes`.

Success: the last line is `# Done. Everything is under …`, and the exit code is 0. If it stops
with `needs tmux` (or git, python3), install that and run it again. If it says the folder exists,
give a new one.

## What it does, step by step

Each step is the same command you would type; [TRANSCRIPT.txt](TRANSCRIPT.txt) is a recorded
run (2026-11-22, Arch Linux, fake agents), with the folder shown as `$WORK`.

| Step | Commands | What to look at in the transcript |
| --- | --- | --- |
| 1. A project | `git init --bare` + `git clone`: a two-file "shop" with a test, and a local remote | `ls` shows `shop.py`, `test_shop.py` |
| 2. Defaults | `pai init --default-agent claude --base main --check "test=python3 test_shop.py" --workers 2 --no-input` | the review check is set **before** the run, so `pai pr check` can use it |
| 3. Two notes | `pai task new … --write` twice, `pai task list` | `2 todo`, in the order lanes get them |
| 4. The run | `pai run --dry-run`, `pai run --yes --wait 20`, `pai status --brief` | lane a gets `add-a-discount` and lane b gets `write-a-readme`; both `task: delivered` |
| 5. The work | the script commits in each lane's worktree, because the fake agent does not edit files | one commit per lane, on `pai/<run>/a` and `pai/<run>/b` |
| 6. Review | `pai pr plan a`, `pai pr check a`, `pai pr check b` | `PASSED` on both; `plan` is `BLOCKED` only because the remote is not on GitHub (exit 1, as expected) |
| 7. Close | `pai cleanup --apply --stop-running` | both workers stopped; the branches stay (`git branch --list "pai/*"`) |

## The vault side: open it in Obsidian

[vault/](vault/) is what the owner sees in Obsidian for a round like this one. It is a snapshot
generated by the round lane's commands (`pai round new`, `pai round status --write-vault`,
`pai round collect --write-vault`) for a round `R-EXAMPLE`
of the same shop project, lanes `a` and `b`.

1. In Obsidian: **Open folder as vault** and choose `examples/two-lane-round/vault`. Any editor
   works too.
2. Open `PAI/Home.md`. Four blocks:
   - one open round;
   - no lane that needs you: both lanes have no tmux window, but no queued items are left;
   - two open decisions;
   - one unapproved handoff (`Agent Inbox/R-EXAMPLE/a/cp-A/HANDOFF.md`, `approved: false`).
3. Follow the links:
   - `PAI/rounds/R-EXAMPLE/ROUND.md` is the board;
   - `a.md` and `b.md` are the lane notes;
   - `PAI/decisions/R-EXAMPLE-D1.md` and `-D2.md` are the decision notes, with `choice:` empty for you;
   - `Agent Inbox/R-EXAMPLE/DECISIONS.md` is the decision sheet they come from.

Without plugins you see the plain tables. With Dataview the `dataview` blocks become live tables.
How to read and answer them: [docs/OBSIDIAN.md](../../docs/OBSIDIAN.md).

In the snapshot, the folders are shown as `<vault>` and `<example>` instead of the machine's real
paths. That is why the notes' `pai_sha256` no longer matches: a real `--write-vault` would treat
them as edited and leave them alone, which is the designed behaviour for notes someone changed.

## With real agents

Replace steps 1 and 5. Work in your own clone from GitHub, and let Claude Code or Codex do the
work. Two things change:

- Each new lane folder asks the agent's **folder-trust question**, which you answer
  (`pai trust`). See FIRST-USE section 6.
- `pai pr open a` then pushes the branch and opens the PR after the check passes. You merge it.

## Clean up

```sh
rm -rf /tmp/pai-two-lanes.XXXXXX     # the folder named on the last line
```

The script started its own tmux server inside that folder; `pai cleanup` already stopped the
agents.
